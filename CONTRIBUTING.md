\# Contributing to NEORUINS



Thank you for your interest in NEORUINS Creator Edition.



NEORUINS is a source-available project under the terms described in `LICENSE.md`.



Before contributing, please review the license and this document.



\## Bug Reports



When reporting a bug, include:



\- NEORUINS version

\- Python version

\- Operating system

\- Description of the problem

\- Steps needed to reproduce the problem

\- Relevant error messages



Never include API keys, access tokens, passwords, `.env` contents, or other private credentials in a bug report.



\## Feature Suggestions



Feature suggestions are welcome.



When proposing a feature, explain:



\- What problem it solves

\- How creators would use it

\- Why it would improve the NEORUINS workflow



\## Code Contributions



Before submitting significant code changes, discuss the proposed change with the project owner.



Contributions should:



\- Preserve existing functionality

\- Follow the existing project structure

\- Avoid exposing credentials or private data

\- Include testing where appropriate

\- Keep publishing actions under explicit user control unless the project design changes



\## Testing



Before submitting code changes:



1\. Confirm the application compiles successfully.

2\. Confirm the main menu starts correctly.

3\. Test the affected workflow.

4\. Avoid publishing test posts to real accounts unless specifically required.

5\. Never use another person's API credentials.



\## Security



Do not publicly report vulnerabilities that could expose credentials or compromise connected accounts.



See `SECURITY.md` for security guidance.



\## Licensing



Submitting a contribution does not change the licensing terms of NEORUINS.



Review `LICENSE.md` before submitting code.



\## Project Status



NEORUINS Creator Edition v1.0.0 is the first public release.



Development is expected to continue as the creator platform evolves.
